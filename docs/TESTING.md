# Проверка платформы и пакета

Сборку и CTest запускайте только на CPU0/CPU1. `rpi4_host_info` читает окружение;
проверка успешного запуска приложения дополнительно требует настоящих Pi4/RT.
Команды сборки: [BUILD.md](BUILD.md).

```sh
piaoip-doctor
systemctl show pi-aoip.service -p MainPID -p CPUAffinity -p ActiveState
sudo taskset -c 0,1 python3 tests/package_lifecycle.py ./dist/piaoip-rpi4_2.1.0-1_arm64.deb lifecycle.json
```

Последняя команда предназначена только для тестовой платы с настроенной службой:
она останавливает, обновляет, удаляет и повторно устанавливает пакет. Не запускайте
её во время работы DAW. Проверяются сохранение конфигурации, поведение остановленной
службы, active upgrade, remove/reinstall и диагностический код неактивного сервиса.

Внешний SDK consumer: `cmake -S tests/consumer -B build/consumer -DCMAKE_PREFIX_PATH=/path/to/sdk`,
затем build/ctest. Общие core-тесты включаются `-DAOIP_BUILD_TESTS=ON`.
Фактическая проверка разделённых исходников: [BUILD-VALIDATION.md](BUILD-VALIDATION.md).

## Измеренная база до разделения репозиториев

На одном физическом стенде Windows 11 x64 ↔ Pi 4 PREEMPT_RT через прямой Gigabit
Ethernet версия 2.1.0 прошла 120 секунд: 64×64, 192 кГц, PCM32, ASIO64, guard512.
Потерь, missing/late/deadline/overflow, просроченных TX и пропусков источника — 0.
Windows отправил 4 608 534 пакета, Pi принял ровно столько же.

| p50 RTT | p95 | p99 | max |
|---:|---:|---:|---:|
| 3,123 мс | 3,148 мс | 3,225 мс | 5,427 мс |

Средняя занятость CPU0 — 92,8%, CPU1 — 57,0%, CPU2/CPU3 — 0%. Запас CPU0 небольшой.
По 5 секунд прошли 8 ASIO-буферов 16–2048 и 7 сочетаний направлений/PCM/частоты.
Эти значения относятся к сборке до выделения репозиториев. Перенос исходников,
новая CMake-сборка и новые пакеты проверяются отдельно; старые цифры не являются
автоматической квалификацией каждого нового бинарника.

RTT — цифровой Pi → ASIO host → Pi через канал 32. Это не ADC/DAC latency,
не повторный тест Ableton и не гарантия максимума на любом ПК. Эффекты на CPU2/CPU3
в этом прогоне не запускались. Для рабочего применения нужен длительный прогон
на целевой системе. Гистограмма RTT насыщается выше 20 мс: крайняя percentile
корзина не является точным значением 20 мс; min/max сохраняют диапазон.
